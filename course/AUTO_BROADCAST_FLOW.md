# Group 9 標準開播流程

這份流程由 [DUAL_LIVE_RUNBOOK.md](DUAL_LIVE_RUNBOOK.md) 取代為目前唯一標準；該文件包含「全部關閉」的完整重啟順序、可直接貼給兩台 Codex 的提示詞，以及最新疑難排解連結。兩台電腦不必在同一個 Wi-Fi；兩台都只連到 Azure 的公開網址與 RTMPS 推流入口。

公開直播網址：`https://group9liveb11302133.japaneast.cloudapp.azure.com/group9/`

## 每次第一位主播開播

1. 在 Azure 確認 VM 是 **Running**，再開啟公開直播網址。
2. 開啟 OBS，確認視窗標題是 `設定檔: Group9 Local - 場景: Group9 Course`。
3. OBS 使用既有的自訂 RTMP 設定；伺服器是 `rtmps://group9liveb11302133.japaneast.cloudapp.azure.com:1936`。設定與金鑰已隨專案保存；使用時不可改寫。
4. 按 **開始串流**。網站約 5–10 秒後第一格會顯示 `LIVE`。
5. 若網站仍離線，先確認 OBS 載入的不是空白預設設定檔，再確認 Azure TCP 1936 可由主播目前網路連線。

## 第二位主播：不同 Wi-Fi／不同網路也可加入

第二位主播不需要連到第一位主播的 Wi-Fi，也不需要第一位主播每次批准。第二台電腦要能連上公開網站與 Azure TCP 1936 即可。

### 第一次一次性設定

1. 第二位在自己的電腦取得專案並開啟 Codex，讀取 [`SECOND_COMPUTER_CODEX.md`](SECOND_COMPUTER_CODEX.md)。
2. 用自己的第二主播帳號開啟公開直播網址，按 **申請成為第二位主播**。
3. 第一位主播只在第一次按一次 **同意加入**；系統會記住這個帳號與固定電腦。
4. 第二台在網站按 **建立固定電腦自動加入**，依網站顯示命令保存固定電腦憑證並安裝 Startup 捷徑。
5. 第二台 OBS 必須使用專案內的 `guest` 推流設定；絕不可使用第一台的 `live` 路徑或金鑰。
6. 在 OBS 啟用 WebSocket 伺服器，連接埠設為 `4455`；設定攝影機、麥克風與 AEC 後做一次實測。
7. 若第二台在不同外網，將該網路的公開 IP 加入 Azure TCP 1936 的白名單；這一步只在外網 IP 改變時重做。

### 後續每次開播

1. 第一位依前一節開始第一路直播。
2. 第二台登入 Windows 後，Startup 捷徑會開啟 OBS、以固定電腦憑證加入 `guest` 路並開始串流。
3. 網站第二格顯示 `LIVE` 即完成；第一位不需要再次操作。

## 網站與互動規則

- 主播可在控制區按 **開啟／關閉麥克風**、**開啟／關閉鏡頭**；每按一次切換一次。
- 一般聊天不朗讀；按 Enter 直接傳送。
- 語音留言與火箭是不同項目。測試版語音留言為 10 點；正式版應調整為 50 點。
- 禮物按點數高低播放；更高點數的新禮物會優先顯示並中斷較低點數動畫。

## 問題排除

| 現象 | 做法 |
| --- | --- |
| OBS 顯示 `Failed to find locale/en-US.ini` | 從 OBS 安裝目錄啟動 OBS，不可把專案資料夾當工作目錄。 |
| OBS 載入空白場景或 RTMP 無法開始 | 重新確認設定檔為 `Group9 Local`、場景集為 `Group9 Course`。 |
| 網站仍顯示離線 | 在 OBS 確認已開始串流，等待 5–10 秒後重新整理網站。 |
| 第二台不同 Wi-Fi 無法串流 | 檢查 Azure TCP 1936 是否將第二台目前外網 IP 加入白名單。 |
| 網站按鈕無法控制 OBS | OBS 啟用 WebSocket、連接埠 4455；第一次完成固定電腦配對。 |
| 第二台一直顯示 Offline | 確認第二台使用 `guest` 路徑與自己的金鑰，而非第一台的 `live` 路徑。 |
